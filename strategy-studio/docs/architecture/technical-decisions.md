# 기술 결정 기록

## ADR-001: 기존 broker를 공통 회계 원천으로 사용 (검토 중)

기존 strategy_engine을 확장한다. Studio·SDK·MCP에 새로운 회계 엔진을 만들지 않는다. 기존 SMA 루프는 회귀 기대값을 유지하는 호환 어댑터로 수렴시킨다. LEAN의 성숙한 기능은 장점이나 KIS/일반 로컬 배포 경로의 Docker 의존성은 사용자 요구에 맞지 않는다. Nautilus의 규모·버전/패키징 요구와 Backtrader GPLv3, vectorbt Commons Clause는 검토 없이 단기 고객 제품에 넣지 않는다. 상세 공식 근거는 경쟁 분석 문서 참조.

## ADR-002: DSL interpreter와 Python worker의 보안 경계 분리

DSL은 타입·노드 수·깊이·기간을 제한한 JSON interpreter, Python은 기존 OS sandbox worker만 허용한다. 임의 Python을 AST 화이트리스트나 일반 subprocess만으로 안전하다고 판정하지 않는다. Windows Python은 검증된 격리가 없으면 거부한다.

## ADR-003: 로컬 SQLite부터 시작

전략/실행 metadata 및 제한된 JSON snapshot을 SQLite에 transaction으로 저장한다. 현재최대5,000봉에서 Parquet를 먼저 추가할 이점보다 패키징·형식복잡도가 크다. 다종목/대형 데이터는 측정 후 확장한다. 저장소 경로는 고객 입력이 아닌 앱 소유 root이며 import/export는 UI 선택 경로와 content를 구분한다.

## ADR-004: 정식 출시 상태 분리

local development, macOS candidate, Windows candidate, signed release를 구분한다. 기존 unsigned extension override는 설치 제품의 정식 업데이트가 아니다. 확인하지 않은 OS·시세·AI 기능은 UI/릴리스 문서에 지원으로 표시하지 않는다.

## ADR-005: 신규 자연어 전략은 선택적 HTTP 초안 생성으로 분리

2026-11-12 구현 결정입니다. **고객용 Studio 엔트리(`runtime.server.main()`)는 `ai_studio=False`로 기동하므로 이 절의 HTTP AI 경로는 고객 배포본에 노출되지 않으며, 내부/개발 환경에서 `create_server(ai_studio=True)`로만 켤 수 있습니다.** 설계 자체는 일반 사용자의 Python·Docker·별도 CLI 설치 없이, 단독 앱의 인증된 로컬 HTTP 화면에서 별도 모델 API 연결을 설정하는 구조입니다. `ai_studio.py`는 HTTP 전용 액션으로 연결·미리보기·생성·조회·취소를 조정합니다. MCP 도구 등록이나 기존 공유 Registry를 변경하지 않습니다. 이 경로는 원본 실행을 요구하지 않으며 가짜 기준 실행을 만들지 않습니다.

`ai_session.py`는 서버 메모리에서 키와 구성을 보관하고 생성 동안 lease로 고정합니다. 공개 상태에는 비밀이 아닌 모델·토큰·시간·연결 ID만 반환합니다. 설정은 인증 성공이 아닙니다. 앱 재시작 시 키를 다시 입력하며 환경변수·다른 앱 설정에서 자격증명을 가져오지 않습니다. HTTP 입력으로 실행파일이나 임의 API 주소를 받지 않습니다. 메리츠 키는 모델 구성에 전달하지 않습니다. 사용자가 요청문에 직접 비밀정보를 적는 것을 완전히 탐지하는 보장은 없으므로 전송 전 안내·확인이 필요합니다.

`ai_http_provider.py`는 고정 Messages endpoint에 한 번 요청하고 자동 재시도하지 않습니다. 파일·주문·도구 권한을 모델에 주지 않으며, 제한된 JSON의 DSL 후보 1~3개만 공통 검증기로 다시 검사합니다. 사용자 데이터 미리보기 외에 고정 지침과 DSL 형식도 실제 전송에 포함됩니다. 토큰·시간·응답 크기를 제한하지만 원격 과금 상한이나 취소 성공을 보증하지 않습니다. 응답 대기·worker 정리의 single-flight 보장은 시험한 고정 Python 3.11 범위이며 다른 버전의 DNS/executor 정리는 별도 검증이 필요합니다.

`ai_drafts.py`는 별도 SQLite 테이블과 원자적 claim으로 요청별 생성을 한 번만 시작합니다. 동의 해시는 요청 데이터·모델 구성·연결 ID·규격 버전에 묶습니다. 재접속 후 키 없이 조회·취소할 수 있고 이미 시작한 요청은 다시 생성하지 않습니다. 저장 실패나 프로세스 종료로 `generating`에 남은 기록은 불확실한 상태로 유지합니다. 프로세스 식별자 일치는 생존 증명이 아니며 자동 재시작하지 않습니다. 취소 제어를 읽지 못한 오류는 사용자 취소와 구분합니다. 완료 트랜잭션 이후 늦은 취소는 저장 성공을 덮어쓰지 않습니다.

초안은 전략 리비전이나 실행 결과가 아닙니다. Studio에서 현재 편집 교체를 확인하고 사용자가 명시적으로 저장·백테스트해야 기존 공통 엔진을 실행합니다. 자동 생성 품질을 성과 보장으로 표시하지 않으며 `modelInvocationVerified=false`를 유지합니다. 조건형 전략 실행과 선택적 Python worker의 경계도 유지합니다.

기존 원본 기반 CLI 개선 coordinator는 별도 서버 주입 경로로 기본 미설정이며 제품 기능으로 노출하지 않습니다. 신규 HTTP 연결이 이를 활성화하지 않습니다. 외부 MCP 호스트의 후보 작성·제출·공통 엔진 재실행 경로(`meritz_ai_request_create`/`meritz_ai_request_get`/`meritz_ai_candidates_submit`)는 고객 경로로 보존합니다. 사용자 절차는 [사용 안내](../user-guide/platform-local.md)를 따릅니다.

## ADR-006: 기존 원본의 HTTP 개선은 공통 제출·엔진을 재사용

2026-11-12 결정입니다. ADR-005와 같이 고객용 Studio 엔트리에서는 꺼져 있는 경로입니다. ADR-005의 초기 전략 초안과 달리, 완료된 DSL 원본을 개선하는 HTTP 경로는 사용자의 동의 후 후보 리비전 저장·동일 데이터와 비용의 재백테스트·비교까지 진행합니다. `AIStudio`의 HTTP 전용 preview/generate 액션에서 같은 `AISession`을 재사용하며 새 엔진이나 제출 파이프라인을 만들지 않습니다. 서버가 만든 trusted binding만 sender와 비밀 제외 metadata를 전달하고 공개 입력은 API 주소·실행파일·임의 metadata를 받지 않습니다. HTTP는 출력 토큰·시간 제한을 표시하며 CLI의 USD 예산 필드를 가짜로 채우지 않습니다.

`ai_requests.source`로 원본 전략·보고서·데이터·설정 해시를 확인한 뒤 `ai_improvement_context`가 공통 `analytics.analyze(report, manifest, bars, settings)`를 다시 실행합니다. 저장된 `analysis`를 모델 근거로 신뢰하지 않습니다. `doctor-v1` 12개 규칙별 상태와 고정 title/message/threshold를 검사하고 허용된 숫자/None evidence만 추출합니다. 회계의 중첩 threshold는 고정 오차 허용값이며 원본 객체 복사가 아닙니다. 최대 크기는 12,000바이트입니다. 원시 봉·가격·거래 ID·사용자 reason·계좌·source label·기업행동 adjustment 원문을 진단 요약으로 전송하지 않습니다. 원래 목적·전략 정의·성과 지표는 별도 사용자 요청 데이터로 전송하므로 사용자 작성 문구의 비밀정보까지 자동 제거한다고 주장하지 않습니다. 진단은 과거 계산 근거와 표본 한계이며 수익 보장이 아닙니다.

preview와 생성 직전 재검증은 같은 prompt helper를 사용합니다. 원본 식별 해시·prompt·모델·제한·connectionId에 묶인 동의 v2로 새 진단 문안을 승인합니다. v1 미생성 preview는 자동 승격하지 않고 새 요청과 동의를 요구합니다. v1 ready/terminal은 저장 당시 동의와 검증된 후보를 보존합니다. ready 재개는 현재 키·설정·lease 없이 후보 해시·규격을 다시 검사하고 공통 submit에서 원본을 다시 검증합니다. CLI/HTTP가 같은 ID를 다른 방식으로 차지하지 못하게 request gate와 generation lock을 공유합니다. read/cancel은 생성 잠금을 요구하지 않으며 모델 생성 중 engine lock을 잡지 않습니다. 새 생성에서 획득한 session lease는 재백테스트 종료까지 유지하는 현재 한계가 있습니다.

보고서 본문 hash 재확인은 기존 `get_run`의 report→manifest 검사와 source의 manifest→request 검사를 보조합니다. valid codec으로 report만 변조한 fresh/ready/disconnected/restarted 회귀에서 추가 모델·엔진·리비전 0회를 확인했습니다. 기존 방어의 재확인이며 새 취약점 수정이 아닙니다. 진단 정책과 분석기의 규칙이 어긋나면 전송 전에 차단하고 현재는 일반 오류로 마스킹합니다. 새 요청만으로 호환성 문제가 복구된다고 보장하지 않습니다.

CLI의 기존 prompt/hash와 외부 MCP 제출 경로는 유지합니다. HTTP 제출 출처는 `local-http-generated`로 구분하고 실제 모델 호출 검증 여부는 false를 유지합니다. 동일 요청의 모델 재호출 금지, 저장 실패·불확실 중단 보존, 취소 marker와 완료 후 늦은 취소의 처리도 공통 경로를 사용합니다. 개선 coordinator 잠금은 현재 POSIX 전용으로 Windows에서 닫힌 상태로 실패합니다. HTTP 개선 경로의 자동 시험은 가짜 모델 응답으로 진단 미리보기·동의 버전 확인·생성 전 취소까지 확인한 범위이며, 실제 모델 호출·과금은 시험하지 않았습니다.


## ADR-007: 조건값 조합 비교는 기존 검증 작업과 공통 엔진을 재사용

2026-11-12 결정입니다. 사용자가 직접 지정한 숫자 조건의 전체 조합을 시험하는 `parameter_grid`를 기존 `validate_robustness`에 추가했습니다. 별도 회계 엔진·작업 저장 종류를 만들지 않고 기존 실행 잠금, `_run_locked`, 후보별 리비전·실행 저장, 검증 결과 조회를 사용합니다. Studio·CLI·MCP는 이 경로를 공유합니다.

대상은 검증된 DSL의 수량, 손절·익절 비율, 실제 상수 노드의 값과 지표 노드의 기간입니다. 경로는 현재 전략에서 열거하며 임의 객체·코드·설정 경로를 평가하지 않습니다. 서로 다른 조건1~3개, 조건당 고유한 유한 숫자1~12개, 전체 조합 최대12개를 허용합니다. 숫자처럼 보이는 문자열·불리언·중복·유효 범위 밖 값은 거부합니다. 전체 조합과 모든 전략 유효성을 먼저 확인하며, `maxEvaluations`를 넘으면 조합 일부만 몰래 실행하지 않고 전체 요청을 거부합니다.

각 후보는 원본과 같은 저장 시세·비용·초기자본으로 독립 실행합니다. 첫 조건을 바깥 반복으로 하는 입력 순서를 유지하며, 같은 수익률은 먼저 나온 후보를 선택합니다. 모든 후보가 성공한 경우에만 후보 중 최고 수익률을 선택하고 실패·악화 결과도 보존합니다. 원본 대비 개선 판단은 원본과 모든 후보의 엔진 버전·Runtime 버전·데이터 해시까지 일치할 때만 제공합니다. 비교 불가 시 개선 여부는 `null`이며 원본 성과를 다른 계산 버전과 조용히 비교하지 않습니다. 이 선택은 같은 관측 자료에 대한 사후 연구이고 독립적인 미관측 검증이 아닙니다.

후보 계획의 순번·조건값·전략 해시는 첫 실행 전에 저장합니다. `get_validation_job`은 최대12개 하위 실행을 인덱스로 조회해 저장된 후보 결과와 대조합니다. 종료된 작업의 미실행 후보와 실행 중의 대기를 구분하고, 결과 저장 전 중단된 하위 실행은 기존 시작 시 복구 정책에 따라 중단으로 표시합니다. 하위 실행 생성 전에 생긴 실패가 최종 작업 저장 전 강제 종료되면 그 실패는 복원되지 않아 미실행으로 표시될 수 있습니다. 전체 작업의120초 제한은 후보 사이와 엔진 판단 시 공유 취소 상태를 확인하는 방식이며 강제 프로세스 종료를 보장하지 않습니다. 취소는 해당 작업을 실행하는 같은 Runtime 프로세스에서만 가능합니다.

알려진 한계: 성공한 하위 실행 이후 비정상 지표·결과 읽기 실패를 후보 실패로 저장하면 작업 조회가 불일치로 거절될 수 있습니다. 현재 정상 엔진 결과에서는 도달하지 않으며 최종 검증 기록은 남습니다. Python 임의 매개변수 변경, Random 탐색, 다종목·환율 최적화는 지원하지 않습니다.
