# 비주얼 빌더 레이아웃 저장 계약

`save_strategy(definition, parentRevisionId=None, editorLayout=None)`는 기존 전략 저장에 선택적인 화면 좌표를 추가합니다. Studio의 기존 `/api/platform` 요청에서 `action: "save_strategy"`와 함께 `arguments.editorLayout`을 전달합니다. 새 엔드포인트·실행 기능은 없습니다. MCP 저장 도구의 입력 스키마는 변경하지 않습니다.

```json
{
  "action": "save_strategy",
  "arguments": {
    "definition": {
      "schemaVersion": 1,
      "kind": "dsl",
      "name": "종가 조건",
      "entry": {
        "op": "gt",
        "left": {"type": "field", "field": "close"},
        "right": {"type": "constant", "value": 100}
      },
      "exit": {
        "op": "lt",
        "left": {"type": "field", "field": "close"},
        "right": {"type": "constant", "value": 90}
      }
    },
    "editorLayout": {
      "entry": {"x": 200, "y": 100},
      "entry.left": {"x": 0, "y": 50.5},
      "buy": {"x": 500, "y": 100}
    }
  }
}
```

## 좌표와 경로

- DSL 정의를 먼저 기존 규칙으로 검증·정규화한 뒤 레이아웃을 검사합니다. Python 전략에는 `{}`를 포함한 레이아웃 객체를 저장할 수 없습니다.
- 레이아웃은 `{DSLpath: {x, y}}` 객체이며 최대 128개 항목입니다. 각 좌표에는 `x`, `y` 두 키만 허용합니다. 두 값은 `bool`을 제외한 유한한 정수 또는 실수이며 **0과 10000을 포함**합니다. 문자열 숫자·NaN·무한대·음수·추가 속성은 거부합니다.
- `entry`, `exit`에서 시작해 실제 노드만 허용합니다. `all`/`any`의 자식은 `.conditions.0`, `.conditions.1`처럼 0부터 시작하는 정규 인덱스이고 재귀적으로 이어집니다. 비교 노드의 피연산자는 `.left`, `.right`입니다. 예: `entry.conditions.0.left`.
- `buy`, `sell`은 DSL의 매수·매도 동작 노드를 위한 특수 경로입니다. 다른 루트, 없는 자식, `.conditions` 배열 자체, `.value` 같은 원시 필드, `entry.0`, 음수 인덱스·앞자리 0이 있는 인덱스는 허용하지 않습니다.
- 경로 문자열은 정의에서 열거한 노드 이름과 비교할 뿐입니다. 코드 평가·동적 속성 접근·파일 접근에 사용하지 않습니다.
- 기존 DSL 제한인 총 64개 조건/피연산자 노드와 깊이 8도 유지합니다. 따라서 현재 정의에서 가능한 레이아웃은 `buy`/`sell`을 포함해 최대 66개입니다. 128개는 별도의 입력 상한이며 DSL 제한을 늘리지 않습니다.

## 저장·복원·호환

전달한 좌표는 반환된 리비전의 최상위 `editorLayout`에 저장됩니다. `get_strategy(revisionId)`와 `list_strategies()`도 이 메타데이터를 그대로 반환합니다. 좌표를 생략한 노드의 배치는 프런트엔드가 결정합니다.

`editorLayout` 생략 또는 JSON `null`은 기존 동작과 동일하며 응답에 해당 필드가 없습니다. DSL에서 `{}`는 명시적인 빈 레이아웃으로 저장합니다. 부모 리비전의 좌표를 자동 상속하지 않으므로 다음 저장에도 유지하려면 프런트엔드가 좌표를 다시 전달해야 합니다. 정의를 편집해 노드가 없어졌다면 해당 좌표도 제거해야 하며, 서버는 잘못된 경로를 조용히 버리지 않습니다.

`hash`는 기존대로 정규화한 **definition만** 대상으로 합니다. 좌표 변경은 실행 의미·정의 해시를 바꾸지 않지만 저장할 때마다 새 불변 리비전을 만듭니다. 원본 리비전은 덮어쓰지 않습니다. `get_strategy`의 기존 정의 해시 검사는 유지하며, 이 해시가 레이아웃 메타데이터까지 인증한다고 해석하면 안 됩니다.

정의 자체의 100,000바이트 제한, HTTP 전체 JSON 요청의 4,000,000바이트 제한, 저장소의 크기 제한은 변경하지 않습니다. 좌표 검증 실패 시 리비전을 생성하지 않습니다. API 키·시장 조회·주문·임의 코드 실행은 이 저장 기능에 포함되지 않습니다.

## 확인 범위

`tests/test_editor_layout.py`는 직접 작성한 기대 경로, 경계 좌표, 잘못된 경로/자료형/추가 속성, Python 거부, 기존 생략/null 응답, 빈 레이아웃, 저장 후 재조회와 별도 Runtime 복원, 입력 객체와 저장 객체의 분리, 부모 보존 및 좌표와 무관한 정의 해시·실행 결과를 검증합니다. 실제 화면의 드래그·배치 검증은 별도 프런트엔드 시험 범위입니다.
