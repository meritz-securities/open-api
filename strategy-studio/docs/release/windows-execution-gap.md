# Windows 실행 지원의 구현 공백

확인 기준: 현재 소스의 읽기 검토. Windows 실행·설치 시험 결과가 아닙니다.

Windows 지원에는 시험 환경 확보 외에도 구현 작업이 남아 있습니다. 설치파일을 만드는 것만으로 Python 전략과 AI 개선 흐름이 지원되는 것은 아닙니다.

| 영역 | 현재 소스 동작 | 완료에 필요한 확인 |
|---|---|---|
| Python 전략 진입점 | Studio는 동봉 WASI 실행기가 있는 경우 Python 편집과 실행을 엽니다. | 배포본의 Studio 화면과 저장된 전략 실행을 확인합니다. |
| 전략 실행부 | `meritz/windows_strategy.py`가 실행마다 동봉 WASI 실행기를 시작합니다. | Windows에서 자원 제한, 시간 초과 후 정리와 재실행을 확인합니다. |
| 전략 작업 프로세스 | 기존 Python SDK와 봉별 판단 규약을 사용하며 코드 전달 전에 WASI 실행기의 제한을 확인합니다. | Windows 설치본의 가상 체결 결과를 검산합니다. |
| 패키지 진입점 | `platform_entry.py`는 작업 프로세스를 계정·앱 모듈보다 먼저 실행합니다. | 이 분리를 유지하고, 격리 작업에 고객 인증 설정이나 불필요한 핸들이 전달되지 않는지 확인해야 합니다. |
| 설치본 검사 | `packaging/windows/verify_native.py --require-python`은 Studio HTTP와 CLI로 합성 데이터의 Python 결과를 검산합니다. | 별도 프로그램이 없는 PC의 실행 경로도 별도로 확인합니다. |
| 로컬 AI 실행 | `runtime/ai_generation.py`와 `runtime/storage.py`의 관련 잠금 경로는 POSIX 환경으로 제한됩니다. | Python 전략 격리와 별개로 Windows의 AI 실행·동시 실행 방지·취소를 구현하고 시험해야 합니다. |

현재 macOS에서 확인할 수 있는 것은 공통 메시지 규격, 잘못된 응답 처리, 플랫폼 분기와 실패 시 실행 거부, 패키지 목록, 기존 macOS 동작입니다. Windows의 실제 권한·파일 접근·네트워크 차단·프로세스 종료·설치 및 제거를 대체하지 않습니다.

Windows 실행 지원은 위 구현과 실제 운영체제에서의 검증이 끝날 때까지 완료로 표시하지 않습니다. 기존 안전하지 않은 실행 거부 동작은 유지합니다.
