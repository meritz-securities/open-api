# 조건 값 비교

완료된 백테스트의 전략에서 수량·손절/익절 비율·조건의 기준값·지표 기간을 바꿔 비교합니다. Python 코드는 대상이 아니며 비주얼 빌더로 만든 전략에 사용할 수 있습니다.

원본 전략과 실행 결과는 유지됩니다. 모든 후보는 원본과 같은 저장 시세, 초기 자본, 수수료·거래세·체결 가격 보정 조건으로 공통 실행 엔진에서 다시 계산합니다. 새 시세를 조회하거나 실제 주문을 보내지 않습니다.

비교할 항목은 최대 3개, 전체 조합은 최대 12개입니다. 예를 들어 수량을 1, 2, 3으로, 손절 비율을 3, 5로 설정하면 6개 조합을 실행합니다. 요청이 한도를 넘으면 일부만 실행하지 않고 수정할 수 있도록 오류를 반환합니다.

원본과 후보의 엔진 버전·실행 환경 버전·시세 식별값이 다르면 원본 수익률은 참고값으로만 표시하고 개선 여부를 판단하지 않습니다. 후보 중 최고 수익률은 원본보다 좋은 결과라는 뜻이 아닙니다. 원본 수익률과 함께 확인하세요. 성과가 나빠진 후보와 실패한 후보도 기록에 남습니다. 후보가 하나라도 실패하면 전체 후보의 최상 결과를 확정하지 않습니다. 같은 시세를 보고 조건을 선택한 사후 비교이므로 미래 성과를 입증하지 않습니다.

진행 중 취소는 해당 작업을 실행 중인 동일 MCP/Runtime 프로세스에 `meritz_platform_cancel`로 작업 ID를 전달할 때만 가능합니다. 별도로 실행한 CLI에서는 다른 프로세스의 작업을 취소할 수 없습니다. 현재 Studio의 실행 화면에는 별도 취소 버튼이 없습니다. 취소하거나 앱이 중단되면 완료된 개별 실행은 보존됩니다. 검증 이력에서 진행 내역을 다시 조회할 수 있습니다. 아직 실행하지 않은 후보는 미실행 상태로 남으며 자동으로 이어서 실행하지 않습니다. 전체 시간 제한은 엔진의 중단 확인 지점에서 적용되므로 정확한 시각에 프로세스를 강제 종료하는 제한은 아닙니다.

MCP에서는 기존 `meritz_strategy_robustness` 도구의 `method`에 `parameter_grid`를 지정합니다. `options.axes`에 허용된 숫자 항목의 경로와 값 목록을 넣고, `maxEvaluations`는 1~12 범위로 설정합니다. 최종 결과는 `meritz_strategy_validation_result`, 작업 진행 내역은 `meritz_strategy_validation_job`으로 조회합니다. 숫자 경로의 예는 `quantity`, `risk.stopLossPct`, `entry.right.value`, `entry.conditions.0.right.value`입니다. 마지막 두 예는 해당 위치가 실제 전략의 숫자 상수인 경우에만 사용할 수 있습니다. 지표 기간은 해당 위치의 `period`를 사용합니다. 각 항목은 중복 없는 유한한 숫자 1~12개를 받아야 하며 전체 조합은 지정한 실행 한도 이하이어야 합니다. 현재 전체 시간 한도는 120초이며 중단 확인 지점에서 적용됩니다. 실제 전략 구조와 도구 설명의 경로 규칙을 함께 확인하세요.

이 기능은 로컬 개발본에 추가 중입니다. 설치형 앱의 지원 여부는 해당 설치본의 릴리스 안내를 확인하세요.
