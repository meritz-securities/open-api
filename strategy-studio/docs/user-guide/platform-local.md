# 전략 만들기와 백테스트 시작하기

먼저 예제 전략을 고른 뒤 매수·매도 조건과 투자 금액을 확인하세요. 과거 시세를 선택하고 실행하면 결과를 볼 수 있습니다. 코드를 작성할 필요는 없습니다. 조건을 연결해 편집하거나, 원할 때만 JSON 고급 편집(모든 OS)과 Python 코드(macOS·Windows)를 사용할 수 있습니다.

- **전략**: 언제 사고팔지 정한 규칙입니다.
- **백테스트**: 과거 시세에 그 규칙을 적용해 가상으로 거래한 결과입니다. 미래 수익을 알려주는 기능은 아닙니다.
- **최대 낙폭**: 자산이 가장 높았을 때부터 얼마나 내려갔는지를 나타냅니다.
- **거래 비용**: 수수료·세금과 예상 가격보다 불리하게 체결되는 차이(슬리피지)를 뜻합니다.
- **전략 버전**: 저장할 때마다 남는 별도 사본입니다. 예전 전략을 덮어쓰지 않습니다.

## 코드 없이 첫 전략 실행하기

1. **예제 전략**에서 시작할 전략을 고릅니다. **선택한 예제 설명**을 펼치면 원래 매수·매도 규칙과 주의사항을 볼 수 있습니다.
2. **이 전략은 이렇게 거래합니다**에서 현재 조건을 확인합니다. 숫자나 조건을 수정하면 이 설명도 함께 바뀝니다. 예제 설명은 원래 설정을 설명하므로 둘을 구분하세요.
3. 처음에는 **직접 조건 편집**에서 기간·수량을 바꾸세요. **노드 연결 편집**은 조건을 선으로 이어 구성할 때 사용합니다. 연결이 빠지거나 조건이 잘못되면 저장·실행할 수 없습니다. 먼저 표시된 입력을 수정하세요. 직접 편집할 수 있는 지표 범위는 아래 **비주얼 빌더에서 편집할 수 있는 범위**를 참고하세요.
4. **전략 저장**을 누른 다음 과거 시세를 선택합니다. 사용법만 연습하려면 **예시 시세로 연습**을 선택할 수 있습니다. 이 가격은 만들어진 예시이며 실제 종목의 투자 성과가 아닙니다.
5. 초기 자본의 통화와 거래 비용을 확인한 뒤 **백테스트 실행**을 누릅니다. 1bp는 0.01%입니다. 예를 들어 0.15%는 15bp입니다. 슬리피지는 예상한 가격보다 불리하게 거래되는 가격 차이를 반영하는 설정입니다.
6. 결과에서 수익뿐 아니라 최대 낙폭과 거래내역을 확인합니다. 조건을 바꿔 비교할 때도 같은 시세·비용을 사용하는지 확인하세요.

기간은 가격 기록 개수를 뜻합니다. 일봉의 20개 기록은 거래가 있었던 20일이며 달력의 20일과 다릅니다. 다른 간격의 데이터를 가져오면 같은 숫자라도 실제 기간은 달라집니다.

## 비주얼 빌더에서 편집할 수 있는 범위

- **직접 조건 편집**의 피연산자는 **가격, 단순 이동평균(SMA), 지수 이동평균(EMA), RSI, 숫자**입니다. 비교는 초과·이상·미만·이하·상향 돌파·하향 돌파, 조건 결합은 AND·OR이며 손절·익절을 추가할 수 있습니다.
- 이 세 지표만 사용하는 예제 8종(SMA 5/20 교차, EMA 12/26 교차, 종가와 20일 평균 교차, 낮은 RSI에서 매 봉 1주, RSI 30 회복 · 70 이탈, SMA 20/60 교차, SMA 교차 + RSI 확인, 한 번 매수하고 보유)은 빌더에서 그대로 수정할 수 있습니다.
- 나머지 예제 27종(WMA·MACD·볼린저밴드·돈치안 등 다른 지표를 쓰는 예제)은 **읽기 전용**입니다. 선택해 저장·실행하고 결과를 비교하는 것은 똑같이 가능하지만, 조건을 바꾸려면 **JSON 고급 편집**에서 조정합니다. 전체 목록은 [전략 예시 고르기](strategy-templates.md)를 보세요.

## 작업 화면

- 왼쪽 **전략 · 예제 · 실행**에서 저장 전략과 최근 실행을 엽니다. 각 최근 목록에서 최대 8개를 표시하므로 전체 보유 목록은 아닙니다. 좁은 화면에서는 이 영역을 펼쳐 사용합니다.
- **예제 전략**을 골라 편집을 시작합니다. 왼쪽 탐색에서 예제를 고르면 현재 초안 교체 여부를 확인합니다. 필요한 미저장 초안은 먼저 저장하세요.
- 전략 편집 화면 상단의 **전략 검증 → 전략 저장 → 백테스트 실행**을 사용합니다. 조건·시세·초기 자본 확인이 끝나지 않으면 실행이 비활성화될 수 있습니다.
- 하단 상태 표시에서 진행·완료를 확인하고 오류가 있으면 **오류 확인**으로 원인을 읽습니다.
- 리포트의 **검증 결과 → 계산에 적용한 비용**에는 저장된 실행의 수수료·매도 거래세·체결 가격 보정률을 %로 표시합니다. 15/20/10bp는 각각 0.15/0.2/0.1%입니다. 값이 없거나 올바른 숫자가 아니면 **기록 없음**으로 표시하며 현재 편집 중인 비용과 다를 수 있습니다. 기술 원문은 기본적으로 접힌 **실행 정보 자세히**에서 열며, 키보드 Enter나 Space로도 열고 닫습니다.

## 실행 방법과 창

베타 기준은 브라우저 모드입니다. 자체 웹뷰 창(`--window`)은 소스의 선택 옵션으로 남아 있으며, 별도의 Python·Docker 설치 없이 동작하는 설치본·업데이트 흐름과 함께 정식 제공 범위는 베타 이후입니다.

| 실행 방식 | 동작 |
|---|---|
| 인자 없음 · `--browser` | 기본 브라우저로 Studio를 엽니다(베타 기본). |
| `--window` | 자체 창을 시도하고, 열 수 없으면 브라우저로 넘어갑니다. |
| `--no-browser` | 창·브라우저를 열지 않고 일회용 접속 링크만 터미널에 출력합니다. 링크는 60초 뒤 만료됩니다. |
| `--mcp` | stdio(기본) MCP 서버로 실행합니다. AI 호스트(Claude Desktop 등)에 연결합니다. HTTP/SSE에서는 플랫폼 도구를 등록하지 않습니다. |
| `--cli templates` 등 | 터미널에서 같은 Runtime을 사용합니다. |

소스는 WebView2가 없거나 자체 창 생성에 실패하면 브라우저로 전환하도록 구성되어 있습니다.

Studio 주소는 `127.0.0.1`의 로컬 포트이며 일회용 티켓이 붙은 링크로만 인증됩니다. 일반 localhost 주소만 열면 인증되지 않습니다. 브라우저의 인증 토큰은 메모리에만 있습니다.

## OS별 지원 범위 (베타 기능 제공 범위이며 실기기 검증 선언이 아닙니다)

| 기능 | macOS | Windows |
|---|---|---|
| 템플릿 35종·비주얼 빌더(DSL) 전략 백테스트 | 지원 | 지원 |
| CSV 시세 가져오기, 메리츠 시세 조회, 리포트·내보내기 | 지원 | 지원 |
| 직접 작성한 Python 전략 실행 | macOS 격리 환경에서 지원 | 동봉 실행기가 있는 패키징 번들에서만 지원(베타 소스 실행에서는 비활성) |

### Windows Python 전략 실행

Windows 의 Python 전략은 동봉 WASI 실행기가 들어 있는 **패키징 번들**에서만 실행됩니다. README 의 소스 실행 절차로 띄운 베타 Studio 에서는
Windows 에서 "Python 코드" 작성 방식이 비활성화되고 "Python 전략 격리 환경이 준비되지 않았습니다" 안내가 보입니다. 이때는 비주얼 빌더(DSL) 전략을 사용하십시오.
macOS 소스 실행에서는 `sandbox-exec` 격리 경로로 Python 전략을 실행합니다.

패키징 번들을 직접 만들어 쓰는 경우에는 `meritz-strategy-platform.exe` 와 같은 폴더의 `_internal` 을 함께 보관하십시오.

DSL은 최대 5,000봉, Python은 최대 1,000봉을 지원합니다.

## 메리츠 시세 조회

1. **메리츠 시세 조회** 또는 **시세** 화면으로 이동합니다. 발급받은 **운영 Open API** App Key와 App Secret을 연결폼에 입력하고 **연결 정보 설정**을 누릅니다. 키는 **앱이 실행 중인 동안 메모리에만** 보관하며 디스크에 저장하지 않으므로, 앱을 종료하면 다시 입력해야 합니다. 브라우저 탭을 닫는 것만으로 연결이 해제되지는 않습니다.
2. 연결 정보 설정은 인증 성공을 뜻하지 않습니다. 이때 토큰 발급이나 시세 조회도 자동으로 실행하지 않습니다. 종목·시장·기간을 입력하고 **시세 조회 후 저장**을 눌렀을 때 실제 조회가 이루어집니다. API 이용 자격과 키 발급은 메리츠 Open API 개발자 포털에서 별도로 준비해야 합니다. 앱은 운영 서버에만 연결합니다.
3. 국내는 6자리 종목코드와 기간을 입력합니다. 시작일과 종료일 차이는 최대 365일이며, 당일·미래 봉은 제외됩니다.
4. 미국 일봉은 조회 시장을 미국으로 선택하고 종목 기호, 거래소(OQ/NY/AX), 시세 구분(실시간 요청 0/지연 요청 1)을 명시합니다. 최대 3년은 앱의 요청 한도이며 공급자의 전체 기간 제공 보장이 아닙니다. 한 번의 요청으로 받은 실제 기간·봉 수와 품질 경고를 확인하세요. 뉴욕 현지 당일·미래 봉을 제외합니다. 가격은 USD이고 초기 자본도 USD로 입력합니다. 시장을 바꾸어도 자본 숫자를 자동 환산하지 않습니다. 배당 현금흐름·분할에 따른 보유 수량 조정·환율 손익은 지원하지 않습니다.
5. 조회에 실패해도 예시 가격으로 자동 대체하지 않으며 기존 데이터를 자동 교체하지 않습니다. 이전 저장 시세가 선택돼 있었다면 출처·기간을 보고 **선택한 저장 시세로 계속**을 명시적으로 선택해야 합니다.
6. **연결 정보 해제**는 앱의 참조를 해제할 뿐 토큰 폐기나 서버 로그아웃을 실행하지 않습니다.

기존 MCP에서 `meritz_studio_open`으로 Studio를 연 경우에는 MCP 프로세스의 연결 구성을 사용하며 연결폼으로 변경하지 않습니다. 단독 앱이 다른 프로그램의 MCP 키를 자동으로 가져오는 것은 아닙니다. 복수 계좌는 Studio에서 선택할 수 없으므로 MCP의 `meritz_platform_data`에서 `account`를 명시해 조회한 뒤 **데이터 목록 새로고침**을 누릅니다. 새로고침은 전략·데이터·실행 목록을 함께 갱신하며 미저장 편집 내용을 저장하거나 교체하지 않습니다.

사용법 연습은 접힌 **연습용 시세**에서 별도로 선택합니다. 만들어진 가격이므로 실제 종목의 투자 성과로 해석하지 않습니다. 시세 파일(CSV) 가져오기는 OHLC 일봉 최대 5,000봉입니다.

## 결과 확인과 내보내기

실행은 저장된 과거 시세를 시간순으로 적용합니다. 조건은 종가로 확인하고 다음 봉 시가에 비용을 반영해 가상 체결하며, 실제 주문은 어떤 경우에도 내지 않습니다. 반복 비교는 같은 시세를 사용하므로 실시간 가격을 기다리지 않습니다. 기본 거래세 0은 고객의 실제 세율을 자동 반영한 값이 아닙니다.

리포트에서 성과·위험·매매 이유를 확인하고 조건을 바꿔 비교합니다. JSON/CSV/HTML을 다운로드할 수 있습니다. CSV의 `recordType=trade`는 거래 행이며 거래가 없으면 숫자를 채우지 않은 `summary` 한 행에 출처를 보존합니다. PDF는 브라우저 인쇄 기능을 사용합니다.

### Walk-forward 사후 검증

완료된 리포트의 검증 결과에서 Walk-forward를 선택합니다. 기준 전략은 자동 포함되며 저장된 추가 전략을 최대 3개 고를 수 있습니다. 학습 봉 수와 평가 봉 수를 지정하면 학습 구간에서 수익률이 가장 높은 후보를 선택해 다음 구간에서 평가합니다. 비교 후보는 실행 전에 고정됩니다. 각 구간을 새로운 계좌 상태로 시작하므로 평가 수익률을 합치거나 하나의 자산곡선으로 해석하지 마세요. 지표 준비 기간보다 구간이 짧으면 거래가 없을 수 있습니다.

이 기능은 이미 본 과거 데이터를 사용하는 사후 연구입니다. 독립적인 미관측 OOS 성과나 미래 수익 보장이 아닙니다. 전체 최대 6개 구간이며 실행 도중 실패한 후보·구간도 표시합니다. 120초가 지나면 협력적 취소 신호를 보내며 현재 계산·저장 단계가 끝날 때까지 초과할 수 있습니다. 시간 제한 또는 취소로 작업이 중단돼도 생성된 개별 실행 기록은 남습니다. MCP에서는 `meritz_strategy_robustness`에 `method="walk_forward"`, `options={"trainBars":80,"testBars":20,"candidateRevisionIds":[]}`를 전달합니다. 봉 수는 보유 데이터 길이에 맞춰 지정하세요.

리포트를 다시 열면 **검증 결과**의 **검증 이력 새로고침**으로 저장 결과를 찾습니다. 전체 최근 검증 작업 100건 중 해당 원본 실행의 작업만 표시합니다. **저장된 결과 열기**는 재계산 없이 결과와 Walk-forward 입력 조건을 복원합니다. 더 오래된 결과는 보존한 검증 ID로 MCP의 `meritz_strategy_validation_result`에서 조회할 수 있습니다.

## 저장 위치와 로컬 데이터 초기화

전략·시세·실행 결과는 고객 PC의 **로컬 SQLite 파일**(`strategy.sqlite3`)에 저장됩니다. 파일은 **암호화하지 않은 평문**이며 OS 파일 권한으로만 보호합니다(macOS·Linux는 소유자 전용 권한, Windows는 사용자 프로필 폴더의 기본 ACL). OS 계정이 침해된 상황을 방어한다고 주장하지 않습니다. 작업 중 DB 파일을 이동하지 마십시오.

| OS | 기본 저장 폴더 |
|---|---|
| macOS | `~/Library/Application Support/Meritz Strategy Platform/` |
| Windows | `%LOCALAPPDATA%\MeritzStrategy\` |
| Linux | `~/.local/share/meritz-strategy/` |

환경변수 `MERITZ_STRATEGY_HOME`을 지정하면 그 경로를 사용합니다. 시세 조회에 입력한 App Key·Secret은 이 폴더에 저장되지 않습니다(메모리에만 보관).

저장된 데이터를 모두 지우는 방법은 두 가지입니다.

1. 앱 안의 **로컬 데이터 초기화** 기능을 사용합니다.
2. 앱을 완전히 종료한 뒤 위 저장 폴더를 삭제합니다. 앱을 다시 실행하면 빈 저장소가 새로 만들어집니다.

삭제한 전략·실행 결과는 복구할 수 없습니다. 필요한 리포트는 먼저 JSON/CSV/HTML로 내보내세요.

## AI 활용은 MCP 경로로만 제공합니다

**Studio는 상용 AI 서비스에 연결하지 않습니다.** Studio 안에는 AI 키 입력, AI 초안 생성, AI 개선 요청 화면이 없으며, Studio가 전략·시세·결과를 외부 AI 서비스로 보내지 않습니다. 화면에 표시되는 기본 개선 후보는 규칙 기반 계산입니다.

AI를 활용하려면 고객이 사용하는 AI 호스트(MCP 지원 클라이언트)에 이 앱을 `--mcp`로 등록합니다. 이 경우 AI 호스트가 전략을 작성하고 아래 도구로 실행하며, **도구 호출 결과는 고객이 연결한 AI 서비스로 전송됩니다.** 해당 서비스의 데이터 처리 정책이 적용됩니다.

- AI 호스트는 `meritz_strategy_templates`로 실제 규격을 읽고 `meritz_strategy_validate` → `meritz_strategy_save` → `meritz_platform_data`(시세 확보) → `meritz_platform_backtest`를 실행합니다. 실제 구현된 도구만 등록되며 백테스트 도구는 실제 주문 함수를 호출하지 않습니다.
- `meritz_strategy_diagnose`로 진단한 뒤 새 정의를 `meritz_strategy_experiment`로 재실행하고 `meritz_platform_compare`로 비교합니다. 성과가 나빠진 결과도 보존됩니다.
- `meritz_strategy_list`는 인자 없이 최근 전략 목록을 반환합니다. 보존한 `revisionId`를 전달하면 목록 범위 밖의 단일 전략 버전도 조회합니다. 단건 조회는 전략 정의의 저장 해시를 검사하며 새 전략이나 실행을 만들지 않습니다.
- 같은 MCP 프로세스의 `meritz_studio_open`을 사용하면 계정 키를 복사하지 않고 같은 Runtime으로 Studio를 엽니다. 창을 다시 열 때 새 실행 링크가 필요합니다.

### MCP 호스트로 개선 후보 만들기

완료된 조건형(DSL) 실행에 대해 AI 호스트가 개선 후보를 제출하는 경로입니다. Python 전략은 지원 대상이 아닙니다.

1. AI 호스트가 `meritz_ai_request_create(runId, purpose)`로 개선 요청을 만들거나, `meritz_ai_request_get`으로 저장된 요청을 읽습니다. `meritz_strategy_list(revisionId=...)`와 `meritz_strategy_templates`로 전략·규격, `meritz_strategy_diagnose`로 계산 근거를 읽습니다.
2. 작성한 정의 1~3개를 `meritz_ai_candidates_submit`에 제출하면 공통 Runtime이 검증하고 별도 전략 버전으로 저장한 뒤 같은 시세·비용으로 백테스트·비교합니다. 원본은 보존됩니다. 같은 요청·같은 후보의 재제출은 저장 상태를 반환하며 다시 실행하지 않습니다.
3. Studio에서는 원본 리포트의 실험 화면에서 **후보 이력 새로고침**을 눌러 저장된 후보를 확인합니다. 전체 최근 실행 100건 중 원본에 연결된 실험만 표시합니다. 성공 후보는 **원본과 저장 결과 비교**로 조회하며 백테스트를 새로 실행하지 않습니다. 데이터·비용·전체 설정의 동일 여부도 함께 확인하세요.
4. **후보 편집 준비**는 후보 전략·데이터·초기자본·비용을 확인한 뒤 전환 선택을 표시합니다. **현재 초안 대신 후보 편집**은 미저장 초안을 교체하므로 필요한 초안은 먼저 저장하세요. 전환 후 저장하면 후보를 부모로 하는 새 전략 버전이 생깁니다.

실패한 후보와 성과가 나빠진 결과도 보존됩니다. 처리 완료는 후보 전부의 성공이나 성과 개선을 뜻하지 않습니다. 서버는 외부 제출 출처를 기록하지만 실제 모델 호출·모델명을 인증하지는 않습니다. 미제출 요청은 `meritz_ai_request_cancel`로 취소할 수 있고, 다른 프로세스에서 실행 중인 작업은 그 프로세스에서 `meritz_platform_cancel(jobId="ai-<requestId>")`로 취소합니다. 후보 이력의 페이지 이동과 ID 직접 입력 UI는 없으므로 오래된 후보 실행 ID는 MCP에서 조회합니다.

## Python 코드 전략

**Python 코드** 탭에서 SDK 예제를 수정할 수 있습니다. `context = Context(ctx)`처럼 감싼 변수에 점을 입력하거나 Ctrl+Space를 누르면 제한된 SDK 도움말을 제안합니다. 원시 `ctx`는 dict이며 `ctx.buy()`처럼 호출하지 않습니다. 수량 자리표시자는 원하는 값으로 채워야 합니다. **전략 검증**은 코드를 실행하지 않고 지원 함수와 문법을 검사하며, 오류 목록에 행·열을 표시합니다. 매우 긴 식이나 중첩이 제한을 넘으면 안내한 위치에서 문장을 나눕니다. Esc 다음 Tab을 누르면 편집기 밖으로 이동합니다. 제공 SDK 외 외부 패키지는 지원하지 않으며, 범용 Python 코드를 비주얼 빌더로 자동 변환하지 않습니다.

## 개발자용 소스 실행

이 절차는 설치형 앱 사용자에게 필요하지 않습니다. 프로젝트 의존성이 설치된 개발 환경에서 `studio` 폴더의 `npm ci`, `npm run build`를 수행하고 `strategy-studio` 폴더의 `python platform_entry.py`로 실행합니다. 실행 옵션은 위 **실행 방법과 창** 표와 같습니다. Windows 실행 지원의 남은 과제는 [Windows 실행 지원의 구현 공백](../release/windows-execution-gap.md)을 확인하세요.

## Claude Code에서 Studio 결과 확인

Claude Code 사용자 설정(`--scope user`)에 전략 전용 MCP 서버 `meritz-studio` 를 등록합니다. 사용자 범위 등록은 어느 폴더에서 Claude Code 를 열어도 쓰이므로
Python 과 `platform_entry.py` 는 **절대경로**로 넣습니다. `strategy-studio` 폴더(`platform_entry.py` 가 있는 곳)에서 한 번 실행합니다.

macOS · Linux:

```sh
claude mcp add --scope user --transport stdio meritz-studio -- "$PWD/.venv/bin/python" "$PWD/platform_entry.py" --strategy-mcp
```

Windows PowerShell:

```powershell
claude mcp add --scope user --transport stdio meritz-studio -- "$PWD\.venv\Scripts\python.exe" "$PWD\platform_entry.py" --strategy-mcp
```

저장소 폴더를 옮기면 `strategy-studio` 폴더에서 같은 명령으로 다시 등록합니다.

패키징 번들에는 같은 등록을 대신해 주는 `Connect-to-Claude-Code.command`(Mac)·`Connect-to-Claude-Code.cmd`(Windows) 가 들어 있습니다. 같은 이름의 기존 서버는 덮어쓰지 않습니다. 새 Claude Code 세션에서 `/mcp` 를 열어 연결 상태를 확인합니다.

- “메리츠 Studio의 지표 예제 중 RSI와 MACD 예제의 매수·매도 규칙을 비교해 줘.”
- “Studio에 저장한 전략 목록을 보여 줘. 최근 백테스트의 전략 이름과 가상 체결 건수도 알려 줘.”

예제 목록은 `meritz_strategy_templates`, 저장 전략은 `meritz_strategy_list`, 최근 실행과 실행별 상세 정보는 `meritz_platform_runs`로 조회합니다. 두 앱이 같은 PC 사용자와 같은 Studio 저장소를 사용할 때 같은 결과가 표시됩니다.
