# 응답 코드표

`rsp_cd` 를 받으셨을 때 찾아보시는 표입니다. 실제 호출로 확인된 값만 담았습니다.

## 먼저 알아두실 두 가지

**1. 이 게이트웨이는 오류를 종류와 무관하게 HTTP 500 으로 냅니다.**
권한이 없어도 500, 날짜 형식이 틀려도 500, 필수값이 빠져도 500 입니다.
403·400·404 는 오지 않습니다. **상태코드가 아니라 `rsp_cd` 로 가르십시오.**

```python
# 잘못된 판정 — 500 을 서버 장애로 읽습니다
if resp.status_code >= 500:
    raise ServerError("서버 오류")          # 실제로는 권한 없음일 수 있습니다

# 올바른 판정 — 본문의 rsp_cd 를 먼저 읽습니다
body = resp.json()
code = body.get("rsp_cd")
```

**2. 무엇을 고쳐야 하는지는 `rsp_sub_msg` 에 있습니다.**
`rsp_msg` 는 "해당데이터가 없습니다." 처럼 두루뭉술한 문장인 경우가 많고,
실제 조치 정보는 `rsp_sub_msg` 에 따로 담겨 옵니다.

| `rsp_cd` | `rsp_msg` | `rsp_sub_msg` |
|---|---|---|
| `7936` | 해당데이터가 없습니다. | `조회시작일` ← 어느 항목이 빠졌는지 |
| `0760` | 권한이 없습니다. | `계좌 관리점과 직원소속부서 확인!!` ← 무엇을 해야 하는지 |
| `5820` | 조회할 내역(자료)이 없습니다. | `종료일자보다 클 수 없습니다.` ← 왜 0건인지 |

`rsp_sub_msg` 는 없을 때도 있습니다. 있으면 사용자에게 함께 보여 주십시오.

## 성공 코드

성공 코드는 계열마다 다릅니다. `rsp_cd == "0000"` 으로 성공을 판정하면
계좌·주문 조회 전체가 실패로 잡힙니다.

| 코드 | 뜻 | 주의 |
|---|---|---|
| `0000` | 정상 | 시세 계열 |
| `0001` | 주문 접수 | **체결이 아닙니다.** `data.warn_cls_code` 를 함께 보십시오 |
| `5762` | 다음 페이지 있음 | 오류가 아닙니다. `tr_cont`·`tr_cont_key` 로 이어 조회 |
| `5766` | 조회 완료 | 계좌·주문 조회 계열 |
| `5820` | 조회할 자료 없음 | **자료가 있어도 이 코드가 오는 API 가 있습니다.** 아래 참조 |
| `5822` | 조회할 자료 없음 | 입출금 계열 |
| `00000` | 실시간 구독 성공 | 관측된 값은 다섯 자리입니다. 자릿수가 REST 의 `0000` 과 늘 다른지는 확인하지 못했으므로, [`07_realtime.py`](../examples/07_realtime.py) 는 `00000` 과 `0000` 을 모두 성공으로 받습니다 |

### `5820` 은 "자료 없음" 의 증거가 아닙니다

이 게이트웨이는 **자료를 담은 채로도 `5820` 을 보냅니다.** 해당하는 API 는
아래 셋이고, 다른 API 도 같을 수 있습니다.

| API | 응답 |
|---|---|
| `GET /accounts/v1/me/collateral` (담보) | `rsp_cd` `5820` · `data` 에 총자산이 들어 있음 |
| `GET /accounts/v1/me/profit-loss/symbols` (종목별 실현손익) | `rsp_cd` `5820` · `data` 9행 |
| `GET /accounts/v1/me/overseas/profit-loss` (해외 실현손익) | `rsp_cd` `5820` · `data` 와 `summary` 가 함께 내려옴 |

**자료 유무는 응답코드가 아니라 `data` 로 판정하십시오.**

```python
# 잘못된 판정 — 담보 총자산을 버립니다
if body["rsp_cd"] in ("5820", "5822"):
    return []

# 올바른 판정 — data 가 비었는지로 가릅니다
rows = body.get("data") or []
if not rows:
    return []          # 이때만 "결과 없음" 입니다
```

## 오류 코드

전부 HTTP 500 으로 옵니다(`EGW00103` 만 403 으로 올 때가 있습니다).

| 코드 | 뜻 | 대응 |
|---|---|---|
| `0760` | 권한 없음 | 앱키·계좌에 그 API 권한이 없습니다. **재시도·토큰 재발급으로 풀리지 않습니다.** 포털에서 권한을 신청하십시오. `rsp_sub_msg` 에 안내가 함께 옵니다 |
| `3174` | 시작일이 종료일보다 큼 | 두 날짜를 바꿔 넣으셨습니다 |
| `3176` | 시작일자를 확인하십시오 | 시작일자가 없거나 허용 범위를 벗어났습니다 |
| `3180` | 시장가·최유리에 단가를 넣음 | `oder_unpr=0` 으로 다시 보내십시오 |
| `5018` | 입력값이 목록에 없음 | 한 바이트 이하 코드값입니다. 허용 코드값을 확인하십시오 |
| `5806` | 거래소 벤더코드 오류 | 거래소 코드 체계가 API 마다 다릅니다 — 시세는 `OQ`, 주문·잔고는 `0537` |
| `6102` | 일자 형식 오류 | `YYYYMMDD` 여덟 자리로 넣으십시오. API 에 따라 같은 상황에서 `IGW50004` 가 오기도 합니다(하이픈이 섞이면 전문 길이가 어긋나기 때문입니다) |
| `7668` | 적용환율을 조회할 수 없는 통화 | 그 통화는 적용환율 고시 대상이 아닙니다. `rsp_msg` 는 "필수 입력 항목이 누락되었습니다." 로 오고 `rsp_sub_msg` 에 `연계기관코드` 가 담깁니다 — **입력 누락이 아니라 통화 문제**입니다 |
| `7936` | 필수 입력 누락 | `rsp_msg` 는 "해당데이터가 없습니다." 로 오지만 실제로는 **필수값 누락**입니다. 어느 항목인지는 `rsp_sub_msg` 에 있습니다 |
| `IGW50004` | 전문 길이 초과 · 필수 누락 | 값의 자릿수가 명세보다 길거나 필수 파라미터가 빠졌습니다 |
| `IGW50006` | 시장구분코드가 그 API 에 맞지 않음 | `mrkt_div_code`·`mrkt_cls_code` 를 그 API 의 설명에서 다시 확인하십시오 |
| `IGW50024` | 필수 헤더 누락 | `mac_address` 를 12자리 대문자 16진수로 넣으십시오 |
| `EGW00002` | 서버측 오류 | 자격증명 문제가 아닙니다. 앱키를 다시 묻지 마십시오 |
| `EGW00103` | 유효하지 않은 `client_id` | 앱키 오타, 또는 **개발 앱키를 운영 서버에 쓴 경우**입니다. 재발급으로 풀리지 않습니다 |
| `EGW00121` | 유효하지 않은 token | 토큰을 새로 받으십시오 |
| `EGW00123` | 기간이 만료된 token | 캐시의 만료 시각이 남아 있어도 서버가 거절합니다. 재발급하십시오 |
| `EGW00200` | 초당 호출 한도 초과 | API 당 초당 10건입니다. 재시도 가능합니다 |
| `EGW00202` | 권한 없음 (게이트웨이 단계) | 실제로는 `0760` 으로 오는 경우가 더 많습니다 |
| `WSC00106` | 실시간 미개방 | 그 서버에서 해당 구독이 열려 있지 않습니다 |
| `WSC00108` | 구독 요청 오류 | `tr_cd`·`tr_key` 형식을 확인하십시오 |
| `WSC00110` | 계정당 최대 세션 수 초과 | 같은 앱키로 열어 둔 웹소켓을 먼저 닫으십시오 |

## 오류가 아닌데 조용히 어긋나는 것들

응답 코드가 정상인데 결과가 틀린 경우입니다. 코드로는 잡히지 않습니다.

- **날짜 형식** — `from`·`to`·`*_date` 에 하이픈이 섞이거나 자릿수가 모자라면
  오류 없이 **기간이 무시된** 자료가 정상 코드와 함께 내려옵니다.
  `market/v1/investors` 는 `from` 이 8자리가 아니면 2년치 655건이, `to` 가 8자리가 아니면 0건이 옵니다
- **거래소 코드 혼용** — 잔고는 `0537`(벤더 코드), 실현손익은 `OQ`(거래소 코드)입니다.
  바꿔 넣으면 오류 없이 0건이 옵니다
- **연속조회 키 훼손** — `tr_cont_key` 는 오른쪽에 공백이 붙어 옵니다. 잘라내면
  다른 구간을 받거나 같은 페이지를 무한 반복합니다. 연속조회가 실제로 동작하는 API 는
  `transactions` · `orders/history` · 해외 `orders/history` · 해외 `exchanges` 네 건뿐입니다
- **국내 시세 `rsp_cd` 손상** — 국내 시세 일부는 `rsp_cd` 에 제어문자가 섞여 옵니다.
  데이터는 정상이지만 업무 성공 여부를 코드로 판정할 수 없습니다.
  대상은 [`corrections.json`](../meritz/data/corrections.json) 에 있습니다

## 판정 순서

```
1) 본문을 JSON 으로 읽는다            (HTTP 상태코드로 먼저 가르지 않는다)
2) rsp_cd 를 읽을 수 있는가
     읽을 수 없으면 → 5)
3) EGW00200 이면 초당 한도 초과다      간격을 두고 재시도할 수 있다
4) 성공 코드인가
     예 → 주문이면 data.warn_cls_code 를 먼저 본다 (경고면 접수되지 않았다)
          자료 유무는 rsp_cd 가 아니라 data 로 판정한다
     아니오 → EGW* 는 게이트웨이 오류(앱키·토큰·호출 방식 문제),
              그 밖은 업무 오류다. HTTP 500 이어도 서버 장애가 아니다
5) rsp_cd 를 읽을 수 없다
     상태코드가 200 이 아니면 → 전송 계층 실패다 (프록시 502 HTML 등)
     200 인데 손상이면 → 알려진 손상 API 인지 확인 (corrections.json)
6) 오류면 rsp_sub_msg 를 사용자에게 함께 보인다
```

동봉한 [`meritz/core/client.py`](../meritz/core/client.py) 의 `judge()` 가 이 순서
그대로입니다. 판정 결과의 `error` 라벨은 이렇게 나뉩니다.

| 라벨 | 언제 |
|---|---|
| `BUSINESS_ERROR` | `rsp_cd` 가 읽히고 성공 코드가 아닐 때 — **HTTP 500 이어도 여기입니다** (`0760` 권한 없음 등) |
| `RATE_LIMITED` | `EGW00200` — 간격을 두고 재시도하면 됩니다 (`retryable=True`) |
| `ORDER_NOT_ACCEPTED` | 성공 코드인데 `data.warn_cls_code` 가 `0` 이 아닐 때 |
| `HTTP_ERROR` | 상태코드가 200 이 아니고 **본문에 `rsp_cd` 조차 없을 때** — 프록시·업스트림 장애 |
| `BAD_RESPONSE` | 상태코드는 200 인데 본문이 JSON 이 아닐 때 |
| `UNREADABLE_RESPONSE_CODE` · `UNVERIFIABLE_STATE_CHANGE` · `EMPTY_RESULT` | `rsp_cd` 가 손상돼 읽히지 않을 때 |
| `READ_ONLY` · `NEEDS_CONFIRMATION` · `INVALID_PARAMS` | 호출이 서버로 나가기 전에 걸렸을 때 |
