# 분할 배분·수량 계산 예제

> **투자권유·투자자문·매매 추천이 아니며, 투자광고가 아닙니다.**
> 예산을 여러 회차로 나눌 때 회차별 금액과 누적 평균단가가 어떻게 되는지,
> 감수할 손실 금액에서 수량이 얼마로 나오는지 계산하는 개발 예제입니다.
> 회차 수·비율·목표는 이용자가 지정하는 값이며, 메리츠증권은 그 값의 적정성을
> 검토하거나 권하지 않습니다. 특정 종목이나 분할 방식을 권유하지 않으며,
> 계산 결과를 주문에 연결하지 마십시오.

## `indicators/` 와 무엇이 다른가

| | `indicators/` | `position_sizing/` |
|---|---|---|
| 입력 | 시장 데이터만 | 시장 데이터 **+ 보유 상태** |
| 출력 | 지표값 | **금액·수량** |
| 같은 입력 → 같은 출력 | 예 | 넘긴 보유 상태에 따라 달라짐 |
| 시그니처 | `evaluate(candles)` | `plan(position, price, ...)` |

금액이 나오기 때문에 패키지를 나눴습니다. 같은 곳에 두면 `indicators/backtest.py`
의 집계 대상으로 빨려 들어가고, 금액이 지표값처럼 읽힙니다.

## 모듈

| 파일 | 계산하는 것 | 산출 상태 |
|---|---|---|
| `money.py` | 수량 내림 · 평단 유도 · 호가 가격단위 | — |
| `position.py` | 보유 상태(예산·평단·수량·회차) | — |
| `split_accumulation.py` | 예산을 N회로 나눌 때 회차별 금액과 누적 평단 | `NOT_STARTED` `ACCUMULATING` `TARGET_REACHED` `BUDGET_EXHAUSTED` `ROUNDS_COMPLETE` `SPLIT_TOO_SMALL` |
| `volatility_sizing.py` | 감수할 손실 금액에서 수량을 역산 | `SIZE_COMPUTED` `SIZE_CAPPED` `SIZE_ZERO` |

두 모듈은 서로 대조됩니다. 앞쪽은 **얼마를 살지를 먼저** 정하고 손실 상한이
없습니다. 뒤쪽은 **얼마를 잃을지를 먼저** 정하고 거기서 수량을 구합니다.

## 산출하지 않는 것

수익률 · 승률 · 최대낙폭 · 연환산 수익 · 목표 도달 소요일.

내는 것은 배분금액 · 누적투입 · 누적수량 · 평단, 그리고 그 평단과 짝이 되는
평가손익 금액과 최대 손실 가능액입니다. **평가손익을 비율로 바꾸지 않는 것은
의도입니다** — 금액은 지금 얼마나 물려 있는지를 알리지만, 비율은 성과 지표로
읽힙니다. 이 규칙은 테스트로 강제됩니다.

## 기본값을 두지 않습니다

`budget` · `splits` · `target_pct` 에 기본값이 없어 호출할 때마다 명시해야
합니다. 함수 안에 `splits=40` 같은 상수를 박으면 **그 숫자가 적정하다는
진술**이 되기 때문입니다. 데모가 쓰는 값은 계산을 보여드리기 위한 예시일 뿐
권장값이 아닙니다.

## 실행

앱키 없이 데모로 확인할 수 있습니다.

```bash
python -m position_sizing.split_accumulation
python -m position_sizing.volatility_sizing
```

실데이터로 계산하려면 앱키를 설정하고 종목코드를 넘깁니다.

```bash
export MERITZ_APP_KEY=발급받은_앱키
export MERITZ_APP_SECRET=발급받은_시크릿

python -m position_sizing.split_accumulation 005930
```

## 구조적 위험

### 분할매수에는 손절 규칙이 없습니다

하락이 이어지면 예산 전액이 투입되고, 그 뒤에도 하락하면 회수 수단이 남지
않습니다. **최대 손실은 투입 원금 전액**입니다(`detail["worst_case"]`).

**평단이 내려가는 것은 손실이 주는 것이 아닙니다.** 5%씩 하락하는 구간을
가정하면 이렇게 됩니다.

```
  회차        가격   수량        평단       평가손익
     1     100,000      1     100,000              0
     3      90,250      1      95,083        -14,500
     5      81,451      1      90,488        -45,186
```

평단은 100,000 → 90,488 으로 내려가는데 평가손실은 0 → -45,186 으로 커집니다.
둘은 반대 방향이 아닙니다. 그래서 이 계산기는 평단과 평가손익을 **언제나 같이**
출력하며, 이 관계는 테스트로 고정돼 있습니다.

- **개별 종목에 "언젠가 오른다"는 보장은 없습니다.** 거래정지·감자·상장폐지면
  영구 손실입니다.
- **N분할이 위험을 나눈다는 뜻이 아닙니다.** 시간만 나눌 뿐 총 익스포저는
  결국 100% 입니다.
- **예산은 전부 잃어도 되는 금액이어야 합니다.**

### 손절 거리는 손절 주문이 아닙니다

`volatility_sizing` 의 손절 거리는 수량을 구하는 데 쓰는 거리입니다. 실제로
손절을 걸지 않으면 위험비율 가정이 성립하지 않고, 걸더라도 갭 하락이면 그
가격에 체결되지 않아 실제 손실이 계산치를 넘습니다. 위험비율은 1회 거래
기준이라 동시에 여러 종목을 들면 그만큼 곱해집니다.

## 한계

- **회차 수·비율·목표는 이용자가 지정하는 값입니다.** 데모의 값은 계산을
  보여드리기 위한 예시일 뿐 권장값이 아닙니다.
- **수익률·손익률·승률을 산출하지 않습니다.** 계산 결과는 산술값이며 매매
  성과의 추정이 아닙니다.
- **수수료·세금·슬리피지·체결 여부를 반영하지 않습니다.** 반영하지 않은 항목은
  결과의 `detail["assumptions"]` 에 함께 실려 나옵니다.
- **직전 회차가 전량 체결됐다고 가정합니다.** 미체결·부분체결이 있으면 다음
  호출의 평단과 회차가 전부 어긋납니다. 상태의 원천은 계좌 잔고여야 합니다.
- **종목을 특정하지 않습니다.** 어떤 종목에 적용할지, 적용할지 여부 자체를 직접
  판단하십시오. 특히 레버리지·인버스 상품은 장기 보유 시 기초지수와 수익률이
  크게 달라질 수 있습니다.
- **호가 가격단위 표는 국내 주식 기준입니다.** ETF·ETN·ELW·채권은 표가 다릅니다.
- 이 저장소의 일봉 API 는 연속조회를 지원하지 않아 40봉이 전부입니다. 분할매수
  한 사이클을 돌려 볼 만한 과거 데이터가 없으므로, **이 저장소에서는 이 방식의
  성과 검증이 불가능합니다.**

## 테스트

```bash
uv run pytest tests/test_position_sizing.py -q
```

계산식 검증에 더해 다음 규칙을 강제합니다 — 예산 초과 불가, 손실 상한 필수
출력, 하락 시 평단 감소와 손실 증가의 동시 성립, 상태값의 매매 어휘 금지,
성과 지표 미산출, 주문 API 미참조.
